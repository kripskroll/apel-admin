👤 À qui s'adresse ce guide ? À la personne qui installe et maintient l'éditeur — vous gérez les dépôts GitHub, créez et distribuez le PAT aux administrateurs, et gérez les incidents techniques. Les utilisateurs finaux (les 2-3 personnes qui éditent les articles) consultent plutôt le guide utilisateur ou le démarrage rapide.

1. Vue d'ensemble

L'éditeur APEL est une page web qui permet à 2-3 personnes de l'association de mettre à jour le contenu du site sans connaissances techniques. Les modifications sont stockées sur GitHub (gratuit, fiable, versionné), et un fichier apel-site-AAAA-MM-JJ.html est téléchargé à chaque sauvegarde pour être envoyé au webmaster de l'école.

Les trois dépôts GitHub utilisés

DépôtContenuRôle
apel-admin L'éditeur lui-même (cette page) Hébergé via GitHub Pages à https://kripskroll.github.io/apel-admin/
apel-site Le fichier apel-site.html du site Chaque sauvegarde y crée un commit. C'est la source unique de vérité.
apel-images Toutes les images des articles Les URLs raw.githubusercontent.com sont insérées dans les articles.

Modèle de partage

Les 2-3 administrateurs partagent un seul compte GitHub (le même que le compte Google Workspace de l'association). Chaque administrateur génère un jeton (PAT) à partir de ce compte, et ce jeton reste sur son propre Mac. Pas d'invitation, pas de gestion d'utilisateurs.

2. Première connexion

Avant de pouvoir sauvegarder, il faut créer un jeton d'accès personnel (Personal Access Token, ou PAT) côté GitHub, puis le coller dans l'éditeur.

2.1 Générer le PAT sur GitHub

Ouvrez github.com/settings/personal-access-tokens/new. Connectez-vous au compte GitHub partagé de l'association si demandé.

Remplissez le formulaire :

ChampValeur
Token nameAPEL admin
ExpirationCustom... → dans 11 mois (max 366 jours)
DescriptionOptionnel — « Jeton pour l'éditeur APEL sur le Mac de Jean »
Resource ownerLe compte GitHub partagé (par exemple kripskroll)
Repository access⦿ Only select repositories — sélectionnez apel-images ET apel-site
Repository permissions → ContentsRead and write
Toutes les autres permissionsLaissez sur No access

Cliquez sur Generate token. La page affiche votre nouveau jeton, qui commence par github_pat_…. Copiez-le immédiatement — il ne sera plus affiché.

⚠️ Ce jeton est un mot de passe. Ne le partagez pas par email/Slack/Discord. Si vous voulez le partager entre administrateurs, mettez-le dans le coffre de mots de passe partagé de l'association (1Password, Bitwarden, etc.).

2.2 Coller le PAT dans l'éditeur

Ouvrez l'éditeur APEL. En haut à droite, vous voyez la barre de connexion :

kripskroll.github.io/apel-admin/
Non connecté à GitHub Connexion
Synchronisé
💾 Sauvegarder

Cliquez sur Connexion. Une fenêtre s'ouvre :

Connexion à GitHub

Pour téléverser des images, il faut un jeton GitHub (Personal Access Token, PAT). Une seule fois par appareil.

  1. Ouvrez la page de génération du jeton (déjà fait à l'étape précédente)
  2. Resource owner = compte de l'association. Repository access = Only select repositories → apel-images et apel-site
  3. Repository permissions → Contents : Read and write
  4. Collez le jeton ci-dessous
Annuler Se connecter

Une fois validé, la barre devient verte avec votre identifiant GitHub. À partir de maintenant, l'éditeur peut sauvegarder.

Combien de fois faut-il faire ça ? Une seule fois par navigateur, sur chaque Mac où vous utilisez l'éditeur. Le jeton est stocké dans le localStorage du navigateur — il survit aux redémarrages.

3. Chargement automatique

À chaque ouverture de la page, l'éditeur essaie de récupérer la dernière version du site depuis GitHub. C'est ce qui garantit que vous travaillez toujours sur la version la plus récente, même si un autre administrateur a sauvegardé depuis un autre Mac.

Le délai initial (~10 secondes)

Le fichier apel-site.html fait environ 2 Mo (à cause des images historiques intégrées). Sa récupération + son analyse prennent quelques secondes. Vous voyez l'écran d'accueil pendant ce temps :

A
Éditeur d'articles APEL
Chargez un fichier apel-site-*.html pour le modifier.
📄 Chargement en cours depuis GitHub…
⏱️ Ne rechargez pas la page pendant ces 10 secondes. Si l'écran d'accueil reste affiché au-delà de 20 secondes, c'est qu'il y a un problème — voir la section Dépannage.

Quand le chargement réussit

Vous arrivez directement sur l'éditeur, avec tous les articles déjà chargés. L'indicateur en haut indique apel-site.html comme nom de fichier.

Quand le chargement échoue

L'écran d'accueil reste visible avec un message expliquant l'erreur :

  • 404 — Aucune version sur GitHub : le dépôt apel-site est vide. Ne devrait arriver qu'à la toute première utilisation, jamais en usage normal.
  • Erreur réseau : votre connexion Internet est coupée. Reconnectez-vous et rechargez.

4. Modifier un article

Sélectionner

Cliquez sur un article dans la liste de gauche. Le formulaire central se remplit avec ses données, et l'aperçu à droite se met à jour en temps réel.

Champs disponibles

ChampDescription
TitreEn rose sur le site. Obligatoire.
DateDate affichée dans la liste et tri.
StatutPublié = visible sur le site. Brouillon = masqué.
Sous-titreEn turquoise. Optionnel.
ImageURL d'une image. Voir section 5 pour téléverser.
Corps du texteÉditeur riche : B gras, I italique, listes, alignement, couleurs (rose / turquoise), liens.
BoutonOptionnel. Texte du bouton + URL. Utile pour « S'inscrire », « Plus d'infos », etc.

Créer / supprimer / réordonner

  • Créer : bouton + Nouvel article en haut de la liste. Apparaît tout en haut, statut Brouillon par défaut.
  • Supprimer : icône 🗑 sur l'article. Confirmation demandée.
  • Réordonner : glisser-déposer avec l'icône ⋮⋮. L'ordre dans la liste = l'ordre d'affichage sur le site.
L'indicateur « ● Modifications non sauvegardées » en haut, à côté du bouton Sauvegarder, devient orange dès que vous modifiez quoi que ce soit. Tant qu'il est là, vos changements ne sont pas sur GitHub.

5. Ajouter une image à un article

Deux méthodes possibles :

5.1 Importer depuis votre Mac (recommandé)

  1. Cliquez sur le bouton 📎 Importer à côté du champ Image.
  2. Choisissez une image sur votre Mac (JPG, PNG, etc.).
  3. L'éditeur la compresse automatiquement en WebP (largeur max 1600 px, qualité 85%) — typiquement de 3 Mo à 200 Ko.
  4. L'image est ensuite téléversée sur le dépôt apel-images de GitHub.
  5. L'URL raw.githubusercontent.com/…/2026-MM-JJ-titre-xxxxxx.webp est automatiquement collée dans le champ Image.
  6. L'aperçu à droite affiche immédiatement la nouvelle image.

Trois messages successifs en bas confirment les étapes : « Compression de l'image… », « Téléversement vers GitHub… », « ✅ Image téléversée ».

5.2 Coller une URL existante

Si vous avez déjà l'URL d'une image (par exemple https://raw.githubusercontent.com/… ou n'importe quel autre lien public), collez-la directement dans le champ Image. L'aperçu se met à jour.

⚠️ N'utilisez pas d'URLs venant de Google Drive ou OneDrive partagés. Ces URLs ne sont pas des liens directs vers l'image et le site les affichera comme une page web entière. Utilisez le bouton Importer à la place.

6. Sauvegarder

Le bouton 💾 Sauvegarder en haut à droite déclenche deux actions en simultané :

  1. Téléchargement local d'un fichier apel-site-AAAA-MM-JJ.html dans le dossier Téléchargements de votre Mac.
  2. Commit GitHub du fichier dans le dépôt apel-site (un nouveau commit s'ajoute à l'historique).

Message de confirmation : « ✅ Sauvegardé : téléchargement + commit GitHub abc1234 ».

Workflow complet : de l'édition à la mise en ligne

  1. Vous modifiez les articles dans l'éditeur.
  2. Vous cliquez sur 💾 Sauvegarder.
  3. Le fichier apel-site-AAAA-MM-JJ.html arrive dans vos Téléchargements.
  4. Vous envoyez ce fichier au webmaster de l'école par email.
  5. Le webmaster le met en ligne sur le serveur du site.
Pourquoi le double mécanisme ? Le commit GitHub est votre filet de sécurité (historique versionné, accessible aux 2-3 administrateurs depuis n'importe quel Mac). Le fichier téléchargé est ce qui finit en ligne — c'est ce que vous envoyez au webmaster.

7. Historique des versions

Chaque sauvegarde crée un commit sur GitHub. Vous pouvez restaurer n'importe quelle version précédente.

Ouvrir l'historique

  1. Si vous êtes dans l'éditeur, cliquez sur 📂 Changer de fichier pour revenir à l'écran d'accueil.
  2. Cliquez sur 🕓 Charger une ancienne version (GitHub).
  3. Une fenêtre liste toutes les sauvegardes, de la plus récente à la plus ancienne :

Versions du site sur GitHub

Cliquez sur une version pour la charger dans l'éditeur.

28/05/2026 14:32 Save apel-site.html 2026-05-28 14:32 a97bfcf Actuelle
28/05/2026 13:25 Save apel-site.html 2026-05-28 13:25 b3f4aa0
27/05/2026 19:20 Save apel-site.html 2026-05-27 19:20 e91d22c

Charger une version historique

Cliquez sur la ligne souhaitée. Le contenu est chargé dans l'éditeur, et une bannière jaune apparaît en haut :

⚠️ Version historique — 28/05/2026 13:25. Sauvegarder écrasera la version actuelle sur GitHub.

À partir de là, deux choix :

  • Restaurer cette version : cliquez sur 💾 Sauvegarder. Un nouveau commit est créé avec ce contenu, qui devient la nouvelle version officielle.
  • Annuler : cliquez sur Revenir à la dernière version dans la bannière jaune.
Aucune version n'est jamais perdue. Restaurer une ancienne version crée un nouveau commit par-dessus — l'historique précédent reste accessible.

8. Dépannage

« Le dépôt du site n'est pas configuré » ou « Pas de jeton GitHub »

Vous n'êtes pas connecté à GitHub. Cliquez sur Connexion en haut à droite et collez votre PAT (voir section 2).

« Jeton invalide (HTTP 401) »

Le PAT a expiré (durée de vie limitée à 366 jours sur GitHub). Allez sur github.com/settings/personal-access-tokens, régénérez le jeton, et collez le nouveau dans l'éditeur (bouton Connexion).

« Commit refusé : HTTP 403 — Resource not accessible by personal access token »

Le PAT existant ne donne pas accès à un des dépôts (probablement apel-site a été ajouté après coup). Allez dans les paramètres du PAT et ajoutez le dépôt manquant dans Repository access → Only select repositories.

« Le fichier a été modifié sur GitHub entre-temps »

Un autre administrateur a sauvegardé depuis un autre Mac pendant que vous éditiez. Rechargez la page pour récupérer leur version (vos modifications locales seront perdues), puis refaites vos changements.

L'écran d'accueil reste affiché plus de 20 secondes

Le chargement depuis GitHub a échoué silencieusement. Vérifiez :

  • Votre connexion Internet est-elle active ?
  • Ouvrez la page du dépôt dans un autre onglet : est-elle accessible ?
  • Si oui, rechargez l'éditeur avec Cmd+Shift+R pour vider le cache.

L'image téléversée n'apparaît pas dans l'aperçu

Vérifiez la console du navigateur (Cmd+Option+I). Si l'erreur indique 403 Forbidden sur l'upload, le PAT n'a pas accès à apel-images — voir l'erreur 403 ci-dessus.

Je veux me déconnecter (autre personne va utiliser ce Mac)

Cliquez sur Déconnexion dans la barre en haut. Le PAT est effacé du localStorage de ce navigateur. La personne suivante devra recoller un PAT pour pouvoir sauvegarder.

Tout est clair ?

Vous savez maintenant tout ce qu'il faut pour utiliser l'éditeur.
